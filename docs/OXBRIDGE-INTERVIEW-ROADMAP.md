# 牛剑面试模块 · 产品规划与迭代路线图

> **核心命题**：牛剑面试不是考核"过去做过什么"或"口语是否流畅"，而是模拟未来的学院辅导课
> （Tutorial / Supervision）。导师关注的是申请者的 **可教性（Teachability）**——面对从未
> 见过的概念或难题时，在引导下如何思考。
>
> 版本：v1.0 · 2026-08-01 · 状态：规划 + 入口页第一阶段实施
>
> 入口：`interviews/oxbridge-interview.html`

## 一、产品定位与差异化

### 1.1 牛剑面试的真实形态（近几年）

| 形态 | 说明 |
|---|---|
| 全程线上化 | 绝大多数国际生通过 Microsoft Teams 或学院指定在线系统进行 |
| 预读材料标配 | 面试前 15–30 分钟进在线等待室，收到从未见过的材料（历史文献 / 法学判例摘要 / 经济数据图表 / 哲学悖论） |
| "接砖与拆砖"对话 | 导师抛出开放性问题 → 申请者回答 → 导师立刻追加反例或修改假设，观察应变 |

### 1.2 申请者最致命的痛点

- **背诵痕迹过重导致秒卡壳**：准备了标准套话，一遇追问/反驳就崩溃
- **"害怕说错"导致沉默**：不知道"把思考过程出声说出来（Think Aloud）"才是得分关键
- **不理解学院风格差异**：圣约翰 / 三一 / 贝利奥尔 等学院出题风格不同，缺切片对比

### 1.3 与普通面试工具的本质区别

| 维度 | 普通名校面试工具 | 本模块（牛剑专用） |
|---|---|---|
| 考核对象 | 简历 + 表达流畅度 | 面对全新问题的思考过程 |
| 内容形态 | 题库 + 标准答案 | 完整追问链 + 思维推演 |
| 交互模式 | 单轮问答 | 多轮"发问→回答→反驳→修正" |
| 反馈来源 | 预设评分 | 语境感知的动态 Hint / 反驳 |
| 数据粒度 | 专业级 | 学科 + 学院 + 题型三维 |

## 二、核心功能模块（四大环节）

```
[预读材料拟真] ➔ [出声思考 + 阶梯Hints] ➔ [导师追问反驳模拟] ➔ [学科+学院面经库]
```

### 2.1 预读材料限时解题器（Pre-interview Reading Simulator）

- **15 分钟倒计时**：倒计时结束前只能看文本/图表；结束后文本收缩至侧边栏，主界面弹出 2–3 个递进式开放性提问
- **四色标注工具**：划线、高亮、批注卡片，用四种颜色对应四维度（见 §3），引导在 15 分钟内快速抓取"核心假设 / 逻辑漏洞 / 潜在争议点"
- **关键耦合点**：前 15 分钟的标注数据直接喂给后端 Hint 引擎——Hint 不预设，而是根据"抓到了哪些点、漏掉了哪些点"动态生成

### 2.2 "出声思考"（Think Aloud）引导卡 + 阶梯式 Hints

- **阶梯式 Hint 按键**：卡壳时可点击
  - Hint 1：提供思考切入角（例："尝试从宏观社会背景与微观个体利益的冲突入手"）
  - Hint 2：提供限定变量（例："如果假设资源是有限的，你会先放弃哪一部分？"）
- **句式救场卡片**：屏幕边缘固定展示牛剑面试高好感度过渡句（如 *"I haven't considered this angle before, but if I break it down based on your point..."*）
- **脚手架撤除机制（关键设计）**：句式卡片定位为"脚手架"而非模板。系统追踪使用频率，当连续多次依赖同一类句式时主动撤除，逼申请者自己组织语言——避免句式卡片变成新的"背诵模板"

### 2.3 追问与反驳模式（Devil's Advocate Challenge）

- **核心**：牛剑面试最核心环节是"导师挑刺"。申请者提交/录制完第一轮回答后，系统自动触发针对性反驳追问
- **技术难点（最高）**：预设反驳是死的，真实导师反驳基于申请者**刚才那句话的具体逻辑**。必须用 LLM 做实时语境感知——读取转写文本，定位论证链条薄弱环节，生成针对性反例
- **失败边界**：一旦做成"题库预设好的反驳"，申请者练两次摸清套路，价值归零
- **反驳方向示例**（法学消防员案例）：
  - 若学生答"A 没有杀人故意，只是选择" → 反驳："选择必然放弃一方，这与'有意让 C 死'在心理状态上有实质区别吗？"
  - 若学生引入"作为/不作为"区分 → 反驳："消防员有职务义务，在此不作为是否等价于作为？"

### 2.4 学科 + 学院（Subject & College）粒度面经数据库

分类筛选必须精确到：

- **学科（Course）**：PPE、HSPS、Law、History、Economics、Natural Sciences 等
- **学院（College）**：牛津 Balliol 偏哲学探究，剑桥 Trinity 偏逻辑推演
- **题型分类**：文本分析题、观点评估题、图表/数据解读题、概念定义题

## 三、四维度拆解框架（核心思维模板）

所有材料无论原型，都能用这四个维度拆。这是产品的"标准思维模板"，也是 Offer Holder 上传内容的审核标尺。

| 维度 | 含义 | 法学示例 |
|---|---|---|
| **文本层 Textual** | 字词的通常意义 vs 法律意义；关键词如何界定 | "故意"如何界定？A"选择救 B"是否构成"故意剥夺 C 的生命"？ |
| **结构层 Structural** | 论证链条：前提→推理→结论；区分裁判理由与附带意见 | 前提=A 的选择直接导致 C 死亡→结论=构成谋杀。但前提有歧义（作为 vs 不作为） |
| **冲突层 Conflict** | 背后的价值张力 | 结果责任（谁死谁负责）vs 行为责任（只惩罚主动杀害）；保护生命 vs 承认救援者两难 |
| **边界层 Boundary** | 什么事实变化会反转结论？反例在哪？ | 若 A 是普通路人（无救援义务），结论是否不同？若 B 是 A 的孩子呢？ |

### 3.1 四维度与四阶段流程的耦合

| 阶段 | 操作 | 与四维度的耦合 |
|---|---|---|
| Phase 1（0–15min 倒计时） | 四色标注：蓝=文本、绿=结构、红=冲突、黄=边界 | 颜色编码本身就是脚手架 |
| Phase 2（倒计时结束） | 弹出 2–3 个递进问题，每个绑定一个维度 | 问题从"该有但学生可能漏标"的维度触发 |
| Phase 3（Think Aloud + Hints） | Hint 引擎读取"标注+转写"动态生成 | 漏标红色→Hint 指向冲突；标了没展开→Hint 限定变量 |
| Phase 4（Devil's Advocate） | LLM 读转写，定位论证薄弱点生成反驳 | 反驳基于学生刚说的话，非预设题库 |

### 3.2 脚手架撤除机制

四色标注是前期脚手架。系统追踪标注行为，当连续 2–3 次模拟都能自发覆盖四个维度时，**主动隐藏颜色提示**，逼从"依赖工具"过渡到"内化思维"。

### 3.3 法学材料的四种原型

| 原型 | 材料形态 | 核心考核点 |
|---|---|---|
| 制定法 + 事实场景 | 一段法条 + 一个边缘案例 | 文义解释、目的解释、漏洞识别 |
| 判例摘要 | 简化版判决书 | ratio decidendi 与 obiter dicta 的区分 |
| 政策困境 | 伦理两难（如见死不救是否入罪） | 价值权衡、立场论证 |
| 概念界定 | 一段描述，问"如何定义 X" | 概念边界、反例构造 |

> **材料压缩原则**：牛剑法学的预读不会给完整判例，而是**把案件压缩成一个两难**，不是压缩成摘要。

### 3.4 学院风格切片

同一材料可提供两种"追问风格"切换：
- 牛津 Balliol：偏法哲学（自然法 vs 实证法的元问题）
- 剑桥 Trinity：偏严密的制定法逻辑推演

### 3.5 STEM 约束-反例型框架（与四维度并行）

> **关键判断**：四维度框架（文本/结构/冲突/边界）是**诠释型思维**的骨架，适用于法学、历史、PPE、文学等"价值权衡 + 文本辨析"学科。STEM 不依赖"冲突层"那种价值张力——它的核心是**给定约束 → 推导可行解 → 追问收紧约束 → 降级/重构解法**。强行套四维度会硬塞（如"冲突层"对 bit 翻转题毫无意义），因此 STEM 使用独立的约束-反例型框架。

| 步骤 | 含义 | CS bit 翻转题示例 |
|---|---|---|
| **约束识别 Constraint** | 题目给定的物理/算法/资源限制是什么？ | 内存硬件 10% 概率翻转 bit |
| **推导路径 Derivation** | 在现有约束下，可行的解法路径是什么？ | 找最大值需遍历，但读取可能出错 |
| **反例收紧 Tightening** | 导师追加新约束，把原解法逼到边界 | 重复读取成本是常规的 10 倍 |
| **降级重构 Degradation** | 放弃确定性，转向概率/近似/降级方案 | 仅对候选最大值二次校验，O(n)→O(k) |

**STEM 样板不显示四色标注**，改用上述四步标签。Hint 引擎对 STEM 的提示逻辑也不同：不是"漏标维度→指向"，而是"未考虑约束收紧→提示边界条件"。

### 3.6 框架选择规则

| 学科 | 框架 | 判断依据 |
|---|---|---|
| 法学 / 历史 / PPE / 文学 / 哲学 | 四维度（文本/结构/冲突/边界） | 诠释型：价值权衡 + 文本辨析 |
| CS / 数学 / 工程 / 物理 / 医学 / 生化 | 约束-反例（约束/推导/收紧/降级） | 模型抽象 + 边界推导 |
| 心理学 / PBS / 实验类社科 | 约束-反例（实验设计变体） | 假设→操作化→反例控制→任务掩护 |

> 选择规则按**思维方式**而非学科标签。PBS 心理学虽属社科，但其推演逻辑属约束-反例型。

## 四、内容样板房（追问链标准格式）

> 牛剑面试记录不能只挂一个问题，必须还原**"导师发问→学生第一轮回答→导师追加条件/反驳→逻辑修正"**的完整推演链条。后继用户才知道按此格式上传。

### 4.1 卡片链标准结构

```
[发问] → [学生第一轮回答] → [导师追问/反驳] → [二次推演] → [拆解卡(含陷阱提醒)]
```

- **[陷阱提醒]** 放进最后的**拆解卡**作为元注释，不打断推演链本身（符合牛剑"先做后思"的考核逻辑）

### 4.2 UI 元数据结构

1. **【专业与学院】**：Oxford - PPE / Balliol College / 2025 Winter
2. **【面试形式】**：Pre-interview Reading + 20 mins Teams Interview
3. **【推演卡片链】**：
   - [发问] 导师抛出的原始材料/问题
   - [陷阱提醒] 容易踩中的背诵式回答
   - [追问拆解] 导师在此环节试图考察的具体思维能力
4. **【一键导出/打印】**：PDF 或文字卡片排版，方便打印带去等候室

### 4.3 初始样板库（全学科覆盖 · 6 个）

> 样板库必须同时覆盖 STEM 与人文社科——两类学科考查的思维能力不同，样板须分别呈现其框架。
> - **人文社科**：考查定义的概念边界、逻辑自洽度、对反例的吸收能力 → 用 **四维度框架**（§3）
> - **STEM**：考查从具体现象抽象出模型、边界条件改变时的归纳推导能力 → 用 **约束-反例型框架**（§3.5）

| # | 样板 | 学科 | 类别 | 考察重点 | 框架 | 状态 |
|---|---|---|---|---|---|---|
| 1 | 法学消防员两难 | Law / 政治哲学 | HSS | 规则边界界定，逻辑一致性 | 四维度 | 已落地（OX-2，详细 worked example） |
| 2 | bit 翻转下找最大值 | CS / 数学 | STEM | 受限硬件下的降级处理与概率思维 | 约束-反例 | 已落地（OX-3） |
| 3 | 1000 米超级风机 | 工程 / 物理 | STEM | 量纲直觉与 Fermi 估计，立方-平方定律 | 约束-反例 | 已落地（OX-3） |
| 4 | 脂质包膜病毒药物设计 | 医学 / 生化 | STEM | 分子机制与临床/演化逻辑结合 | 约束-反例 | 已落地（OX-3） |
| 5 | 邮件比手写信更易撒谎 | PBS / 心理学 | HSS（跨界） | 实验设计与变量控制（操作化） | 约束-反例（实验设计变体） | 已落地（OX-3） |
| 6 | AI 文本 vs 17 世纪诗 | 现代语言 / 文学 | HSS | Unseen 细读，意图 vs 接收美学 | 四维度 | 已落地（OX-3） |

> **跨界说明**：PBS 心理学样板虽属社科，但其"假设→操作化→反例控制（霍桑效应）→任务掩护"的推演逻辑更接近 STEM 的约束-反例型，而非人文社科的文本-冲突分析。这印证了框架需按**思维方式**而非**学科标签**选择。

### 4.4 法学 Worked Example（消防员两难）

**材料（压缩成两难）**：
> 法条："任何人故意剥夺他人生命者，处谋杀罪。"
> 事实：消防员 A 在火场中只能救一人——救 B 则 C 死，救 C 则 B 死。A 选择救 B。C 的家属控告 A 谋杀。

**四维度拆解**：
- 文本层："故意"如何界定？A"选择救 B"是否构成"故意剥夺 C 的生命"？还是仅"未阻止死亡"？
- 结构层：前提=A 的选择直接导致 C 死亡→结论=构成谋杀。但前提有歧义（作为 vs 不作为）
- 冲突层：结果责任 vs 行为责任；保护生命 vs 承认救援者两难
- 边界层：若 A 是普通路人（无救援义务），结论是否不同？若 B 是 A 的孩子呢？

**递进问题**：
1. "故意"在该场景中应如何界定？A 的心理状态是什么？
2. 不作为能否构成"剥夺生命"？区分标准是什么？
3. 给出一个让结论反转的事实变体。

## 五、迭代路线图

### Phase 1：入口重构 + 全学科样板库（OX-1 ~ OX-3）

> 目标：把静态科普页改造为模块化入口，建立全学科覆盖的内容样板房（双框架）

| 版本 | 交付物 | 反馈检查点 |
|---|---|---|
| **OX-1** | 入口页重构：模块架构导航（四大环节入口）+ 修正现有样题硬伤 + 新增四维度拆解框架说明 | 导航是否清晰 |
| **OX-2** | 法学 Worked Example 落地（消防员两难 + 四维度拆解卡 + Devil's Advocate 追问链静态展示） | 样板是否"可学" |
| **OX-3** | 全学科样板库落地（CS/工程/医学 STEM 三题 + PBS/文学 HSS 两题），STEM 用约束-反例框架，HSS 标注四维度适用 | 双框架迁移性 |

### Phase 2：预读材料模拟器（OX-4 ~ OX-7）

> 目标：可交互的限时解题器

| 版本 | 交付物 | 反馈检查点 |
|---|---|---|
| OX-4 | 15 分钟倒计时 + 文本展示 + 四色标注工具（蓝/绿/红/黄） | 标注手感 |
| OX-5 | 倒计时结束→文本收缩侧边栏 + 弹出递进问题（绑定维度） | 流程连贯 |
| OX-6 | 标注数据结构化存储（localStorage）→ 喂给 Hint 引擎 | 数据可用性 |
| OX-7 | 法学/历史/PPE 各 1 份预读材料 | 内容质量 |

### Phase 3：Think Aloud + 阶梯 Hints（OX-8 ~ OX-11）

> 目标：动态提示，非预设题库

| 版本 | 交付物 | 反馈检查点 |
|---|---|---|
| OX-8 | 录音 + 转写（Web Speech API / 第三方） | 转写准确率 |
| OX-9 | 阶梯式 Hint 按键（Hint 1 切入角 / Hint 2 限定变量） | 提示是否"点到为止" |
| OX-10 | Hint 引擎：读取"标注 + 转写"动态生成（漏标维度→指向；标了没展开→限定） | 动态性 |
| OX-11 | 句式救场卡片 + 脚手架撤除机制（追踪频率，过度依赖时撤除） | 是否避免新模板化 |

### Phase 4：Devil's Advocate（OX-12 ~ OX-15）

> 目标：语境感知的实时反驳（最高技术难度，最核心差异化）

| 版本 | 交付物 | 反馈检查点 |
|---|---|---|
| OX-12 | 转写文本→论证链条解析（前提/推理/结论定位） | 解析准确率 |
| OX-13 | LLM 生成针对性反驳（基于学生刚说的话，非预设题库） | 反驳真实感 |
| OX-14 | 反驳后二次推演引导（承认局限+顺新条件推理） | 推演引导 |
| OX-15 | 学院风格切换（Balliol 法哲学 / Trinity 逻辑推演） | 风格差异感 |

### Phase 5：面经数据库 + UGC（OX-16 ~ OX-20）

> 目标：Offer Holder 自发上传追问链

| 版本 | 交付物 | 反馈检查点 |
|---|---|---|
| OX-16 | 学科+学院+题型三维筛选 | 筛选精度 |
| OX-17 | UGC 上传表单（按 §4 标准格式） | 上传门槛 |
| OX-18 | 内容审核标尺（四维度覆盖度校验） | 内容质量 |
| OX-19 | Offer Holder 还原计划入口（1–2 月发 Offer 季招募） | 招募转化 |

## 六、实施优先级判断

### 6.1 学科覆盖：STEM 与人文社科并行（双框架）

- **两类学科考查的思维能力不同，须并行覆盖**：
  - 人文社科（法学/PPE/历史/文学）：用四维度框架（文本/结构/冲突/边界），考查定义边界、逻辑自洽、反例吸收
  - STEM（CS/工程/医学/生化）：用约束-反例框架（约束/推导/收紧/降级），考查模型抽象与边界推导
- **框架按思维方式选择，而非学科标签**：PBS 心理学虽属社科，但其"假设→操作化→反例控制"逻辑属约束-反例型，归入 STEM 框架
- **初始样板库已覆盖 6 个学科**（法学 + CS/工程/医学 + PBS/文学），两类框架均有样板验证，UGC 上传时按 §3.6 选择规则引导

### 6.2 路径先后

- **路径 1（拆解流程）先行**：本质是产品"内容样板"。无样板则 Offer Holder 上传内容参差不齐，既无法审核，后来者也无从学习
- **路径 2（激励机制）后行**：有样板后，激励核心不是"给钱/给积分"，而是让 Offer Holder 觉得"我的回忆录能成为后辈的标准教材"——身份认同驱动比物质激励更持久

## 九、LLM 接入说明（Devil's Advocate 升级）

> 当前 Devil's Advocate（OX-12~15）使用**关键词规则引擎**模拟反驳。这是无后端、无 API key 的降级方案，能跑通交互链路但反驳缺乏语义理解。接入 LLM 后，反驳将基于学生回答的真实语义生成，更贴近真实导师。

### 9.1 需要用户做什么

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 选一家 LLM 服务商并注册 | 推荐 OpenAI / Anthropic / 智谱 GLM（国内可用，免翻墙） |
| 2 | 获取 API Key | 在服务商控制台创建 API Key，复制保存 |
| 3 | 提供给开发环境 | 方式 A：填入前端配置（仅本地测试，会暴露 key）；**方式 B（推荐）**：部署一个轻量后端代理，前端调 `/api/devils-advocate`，key 存后端环境变量 |
| 4 | 确认费用预算 | 见 §9.3 |

### 9.2 服务商选择建议

| 服务商 | 模型 | 优势 | 适合 |
|---|---|---|---|
| 智谱 GLM | glm-4-flash / glm-4 | 国内可直连、中文好、有免费额度 | 国内用户首选 |
| OpenAI | gpt-4o-mini | 反驳质量高、生态成熟 | 有海外卡 |
| Anthropic | claude-3-5-haiku | 推理强、安全 | 有海外卡 |
| DeepSeek | deepseek-chat | 极便宜、国内可用 | 预算敏感 |

### 9.3 费用估算（每次 Devil's Advocate 反驳）

单次反驳约消耗：输入 ~800 token（材料+学生回答+提示词）+ 输出 ~300 token（反驳文本）≈ 1100 token。

| 服务商 | 模型 | 单价（输入/输出 每 1M token） | 单次成本 | 月成本（日均 50 次） |
|---|---|---|---|---|
| 智谱 GLM | glm-4-flash | ¥1 / ¥1 | ≈ ¥0.001 | ≈ ¥1.5 |
| 智谱 GLM | glm-4 | ¥50 / ¥50 | ≈ ¥0.055 | ≈ ¥82 |
| OpenAI | gpt-4o-mini | $0.15 / $0.60 | ≈ $0.0003 | ≈ $0.45 |
| DeepSeek | deepseek-chat | ¥1 / ¥2 | ≈ ¥0.0014 | ≈ ¥2 |

> **结论**：用 glm-4-flash 或 deepseek-chat，月成本 **¥2~¥3**，几乎免费；用 gpt-4o-mini 月成本约 **$0.45（¥3）**。

### 9.4 接入后的代码改动

```javascript
// devils-advocate.html 中，将 generateChallenge() 替换为：
async function generateChallengeLLM() {
  const res = await fetch('/api/devils-advocate', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      materialId: state.materialId,
      style: state.style,
      studentAnswer: state.answer,
      chainParsed: state.chainParsed
    })
  });
  const data = await res.json();
  return data.challenge;  // { text, weakness, style }
}
```

```javascript
app.post('/api/devils-advocate', async (req, res) => {
  const { materialId, style, studentAnswer } = req.body;

```

### 9.5 升级路径

- **阶段 1（当前）**：规则引擎，零成本，跑通交互
- **阶段 2**：接 glm-4-flash / deepseek-chat，月成本 ¥2~3，反驳有语义理解
- **阶段 3**：接 gpt-4o-mini，反驳质量更高，月成本 ¥3~5
- **阶段 4**：多模型对比 + A/B 测试，选最优性价比

### 10.2 修改原则

1. **先改 roadmap，再改代码**：任何新功能/新版本必须先在本文档登记版本号（OX-N）和交付物，再实施
2. **双框架不可混用**：人文社科用四维度（文本/结构/冲突/边界），STEM 用约束-反例（约束/推导/收紧/降级），PBS 等实验类用约束-反例实验变体
3. **数据互通**：simulator 的标注 → localStorage `oxbridge_sim_annotations` → hints 读取；hints 的转写 → URL 参数 → devils-advocate 读取。改数据结构时三处同步
4. **种子数据在 bank.html 的 `SEED_BANK` 数组**，用户上传存 `localStorage.oxbridge_user_bank`

### 10.3 新增学科样板的步骤

1. 在 `MATERIALS` 对象加材料（simulator.html + hints.html + devils-advocate.html 三处同步）
2. 判定框架：人文社科→四维度，STEM→约束-反例
3. 若是 STEM，在 `HINT_BANK` 加 Hint 文案（约束/推导/收紧/降级四步）
4. 若有 Devil's Advocate 需求，在 `CHALLENGE_RULES` 加 pattern 匹配规则
5. 在 bank.html 的 `SEED_BANK` 加种子面经

### 10.4 用户使用指引（OX-24 落地）

每个模块页面顶部加"使用指引"引导区，包含：
- 本环节在真实面试中对应什么
- 建议操作顺序（1→2→3）
- 完成后跳转到哪个模块
- 核心提示（如"沉默比说错更致命"）
