# 抖科 Douke · 引擎 20 版本迭代优化规划

> **核心目标**：从"模拟规则引擎"逐步迭代至"能理解用户的自适应出题引擎"
> **方法**：多个方案并行、反复模拟测试评估、重构以往做题模式、每次迭代有量化的打分系统对照
> **覆盖范围**：推荐算法 · 题库生成 · 难度自适应 · 用户画像 · A/B 实验框架 · 交互体验
> **周期假设**：每版本迭代 1-3 天（视复杂度），20 版本 ≈ 6 周到 2 个月
> **评分依据**：使用 `DoukeScoring` 打分系统 5 维度（题库质量 / 行为健康度 / 推荐效果 / 题库健康度 / 方案对比）

---

# 第一阶段：基础稳固 (v1.0 — v5.0)

## v1.0 「地基」— 题库打底 + 规则引擎 v1 + 打分系统上线
- **迭代目标**：把"题库 + 简单推荐 + 打分"三件套跑通，数据有来有回
- **关键改动**：
  - 接入 `DoukeQB` 400+ 简单题库（8 科目，每题含 score 元数据）
  - 规则引擎 v1：新鲜度(0.1) + 科目轮换(0.3) + 难度系数(1.4×阈值) + 权重加权
  - 接入 `DoukeScoring`：
    - 启动时展示题库质量报告（整体均分 + 分布直方图 + 各科目均分）
    - 每完成 5 题刷新推荐引擎效果分（多样性/曲线平滑/新鲜度/正确率适配）
    - 答题行为记录（停留时长、正确率、反馈）持久化到 localStorage
  - **并行方案（3 套）**：
    - `A-plan`：加权随机（当前 v1 版本）
    - `B-plan`：Round-Robin 科目轮询（不加权，保证覆盖面）
    - `C-plan`：纯简单题优先（80% easy / 20% medium）
  - **成功指标**：
    - 题库健康度 ≥ B (≥80)
    - 单会话 ≥ 20 卡停留率 ≥ 60%
    - 三套方案模拟 A/B 报告（`DoukeScoring.simulateAB`）可正常输出排名
- **风险**：题库某些科目题量偏少导致轮换受限 → v1.x 逐步补题
- **产出物**：`scoring-report-v1.json`（模拟 A/B 50 步结果）

## v1.5 「广度补足」— 每科目补到 60+ 题，难度分布 5:4:1
- 迭代目标：消除偏科，保证推荐引擎有"内容可挖"
- 关键改动：
  - TOEFL/IELTS/AMC/A-Level/IB 重点学科各补 20-30 题
  - 难度强制比例：50% easy / 40% medium / 10% hard
  - 新增题型：true/false、3 选项、配对题（先小比例试点）
- 打分检查：`DoukeScoring.bankHealthScore` sufficiency 每项 ≥ 80
- 并行方案：沿用 v1.0 三套 A/B，验证题量增加后排名是否稳定
- 成功指标：8 科目 sufficiency 全过 80 分

## v2.0 「信号扩展」— 7 种隐式信号接入 + 权重自动调优
- **迭代目标**：推荐不再只靠"答题对错"，而是全面捕捉用户行为
- **关键改动**：
  - 新增信号采集：
    - `swipeSpeed`：滑动速度 px/ms（快=不感兴趣）
    - `revisitRate`：是否按 prev 回看
    - `answerLatency`：选项点击距卡片显示的时间（秒选=不会/太简单）
    - `scrollDepth`：卡片滚动到底部比例（没看全=不关心）
    - `feedbackBtns`：太简单/正好/太难 显式反馈
    - `bookmark`：收藏（强正面信号）
    - `choiceChanges`：改选项次数（犹豫=难题）
  - 推荐引擎 v2：7 种信号线性加权（初始权重手动设，v3 自动调）
  - 打分系统升级：`behaviorScoreForCard` 额外用 7 信号中的 3 种辅助判分
- **并行方案（3 套 +1）**：
  - `A-plan`：v1.x 加权随机（baseline）
  - `D-plan`：SwipeSpeed × dwell 双信号主导（兴趣导向）
  - `E-plan`：准确率 + answerLatency 双信号主导（能力导向）
  - `F-plan`：等权重 7 信号平均
- **成功指标**：推荐引擎效果分 ≥ A-plan + 5 分（模拟 A/B 50 步）
- **产出物**：7 维度信号热力图（每个信号对正确率的 Pearson 相关系数）

## v2.5 「错题回环」— 做过错题在 T+1/T+3/T+7 节点自动回放
- 迭代目标：错题不再一次性
- 关键改动：
  - 答错后，在记录中标记 `wrongCount`、`lastWrongTs`
  - v2 推荐引擎额外项：错题库 Ebbinghaus 衰减因子
  - 错题回放时标记 "Review Card" 徽章
- 打分检查：错题第二次出现正确率 ≥ 第一次 1.3×

## v3.0 「权重调优」— 网格搜索 + 爬山法自动寻优参数
- **迭代目标**：从"拍脑袋权重"过渡到"仿真择优"
- **关键改动**：
  - 推荐引擎权重参数集 Θ = {freshness, subjectRot, difficultyAdj, typeDiversity, ...} 共 8 个参数
  - 定义目标函数 `F(Θ) = 0.5 × 推荐引擎效果分 + 0.3 × 答题正确率 + 0.2 × 平均停留时长/理想时长`
  - 执行 200 次仿真会话（虚拟学生模型）：
    - 方案一：网格搜索（2^8 组合的粗搜 + 细搜）
    - 方案二：随机爬山（每步随机扰动最优解附近 + 模拟退火）
  - 最终选 F 最高的 2 组参数，与 baseline 做真实 A/B 30 会话对比
- **并行方案**：
  - `Baseline-v2`：人工权重
  - `GridSearched-v3`：网格搜索最优
  - `HillClimb-v3`：爬山法最优
- **成功指标**：至少 1 个自动调优方案 F 值 ≥ Baseline + 8 分
- **产出物**：`params-v3.json`（最优参数集 + 寻优过程曲线数据）

## v3.5 「科目画像」— 各科目独立能力估计（ELO 风格）
- 迭代目标：不再只有全局正确率，而是分科目的 θ_能力值
- 关键改动：
  - 每科目维护 ELO 风格分 `ability[subject]`，初始 1200
  - 答对：Δ ∝ (题目困难度 - 当前ability)
  - 答错：-Δ 对称
  - 推荐时：ability 与题目目标区间匹配得分函数（Gaussian kernel）
- 打分检查：同科目正确率随 ability↑ 先降（因为推难题）后稳

## v4.0 「难度标定」— 题目 IRT 参数估计 (mock) + 动态难度标签
- **迭代目标**：题目标称难度(标签) → 实际难度(从数据学到)
- **关键改动**：
  - 每题赋予 3 参数 IRT（1PL Rasch 起步）：
    - `b` 难度参数（初始 = 标签映射：easy=-1 / medium=0 / hard=+1.5）
    - 从答题记录用 MLE 估计真实 b
    - b 值每天滚动重算，5 样本以上才生效
  - 推荐难度自适应：P(答对|user_ability, b_item) = 1/(1+exp(-(θ-b)))，目标 P=0.67，推最接近的题
  - 打分系统新增 `difficultyMatch` 实时监控：实际 P(答对) 与目标 0.67 的偏差
- **并行方案**：
  - `FixedDifficulty`：v3 baseline（只用标签）
  - `IRT-1PL`：动态 b 估计 + 目标 P=0.67
- **成功指标**：IRT 方案 difficultyMatch 维度 ≥ Fixed + 10 分
- **产出物**：题目 b 值快照 `irt-params-v4.json`（≥ 200 题有样本）

## v4.5 「卡片类型多样化」— 每 8 张插入 1 张知识点卡或进度卡
- 迭代目标：避免连做题目疲劳
- 关键改动：在推荐队列中硬约束（`typeRotation` 增强）：
  - 连续 question ≤ 5 张；
  - 每 8 张穿插 1 张 knowledge / progress / tip / deadline
- 打分检查：推荐引擎 diversity 维度 ≥ v4.0 + 5 分

## v5.0 「阶段验收」— 第一阶段总结 + A/B 大战
- **迭代目标**：把 v1-v4.5 所有方案做一次"总决赛"，确立 v6 baseline
- **关键改动**：
  - 参赛方案（≥ 6 套）：
    - v1.0 加权随机
    - v2.0 七信号线性
    - v3.0 GridSearch 最优
    - v3.5 ELO 能力匹配
    - v4.0 IRT-1PL
    - v4.5 类型平衡版（基于最优方案 + type 硬约束）
  - 模拟 100 会话 × 每会话 80 卡，跑 `DoukeScoring.simulateAB`
  - 输出综合排名、每种方案的 5 维度雷达图
  - 人工抽检 10 条会话卡片序列（避免只靠打分过拟合）
- **成功指标**：冠军方案推荐效果总分 ≥ v1 baseline + 15 分
- **产出物**：
  - `ab-finals-v5.md`（决赛排名 + 雷达图 + 人工点评）
  - `champion-params-v5.json`（冠军参数包）
  - 阶段报告：题库健康度、答题分布、冷启动前 10 题序列分析

# 第二阶段：算法进阶 (v6.0 — v10.0)

## v6.0 「统计模型入门」— Logistic 回归替代手搓权重
- **迭代目标**：模型从规则 → 可学习的线性模型
- **关键改动**：
  - 标签定义：用户对卡片"是否满意"（proxy：dwell > ideal×0.5 且 未按 prev 且 feedback!="hard"）
  - 特征 12 维：{seenRecency, sameSubjectCount, difficultyGap(θ-b), topicWeight, feedbackBookmark, accuracyBySubj, dwellMeanLast3, ...}
  - 训练集：本地 `DoukeScoring.records` + 100 模拟会话合并
  - 用简单的梯度下降训练 LR（手写，无外部依赖），输出每卡的 `P(满意|x)`
  - 推荐：Top-K P(满意) + 少量 ε-greedy 探索（ε=0.1）
- **并行方案**：
  - v5 冠军（规则）
  - LR-Learned-v6（模型）
- **成功指标**：LR 方案会话级"满意 proxy 率" ≥ 规则 + 5%
- **产出物**：12 维权重向量 + 每维含义解释（正/负系数）

## v6.5 「ε-greedy 调参」— 探索与利用平衡
- 改动：ε ∈ {0.02, 0.05, 0.1, 0.2} 四组并行模拟，选长期累积回报最高（前 5 会话 vs 20 会话对比）
- 产出：`epsilon-sweep-v65.png`（数据点表）+ 推荐 ε 值

## v7.0 「画像 v2」— 8 维度用户画像 + 聚类分析
- **迭代目标**：用户不是"一个标量"，而是 8 个维度上的"形状"
- **关键改动**：
  - 画像维度：
    1. 总体能力（加权 ELO）
    2. 科目偏好向量（8 科 softmax）
    3. 难度偏好（喜欢挑战 vs 保成功感）
    4. 节奏偏好（快刷 vs 精读）——从 dwell、swipeSpeed 学
    5. 题型偏好（选择 vs 知识点 vs 进度）
    6. 反馈敏感度（feedbackBtn 使用率）
    7. 坚持力（会话平均卡数 × 连续天数）
    8. 记忆力系数（错题回访正确率拟合出的 SRS 半衰期）
  - 用 mock 50 用户数据做 K-Means(K=4) 聚类：
    - "学霸挑战型"
    - "稳步积累型"
    - "碎片快刷型"
    - "需要鼓励型"
  - 推荐时画像匹配：每种 cluster 预调推荐权重模板
- **打分系统升级**：新增 `personaFit` 维度（行为是否与画像匹配）
- **产出物**：用户画像快照 + 4 类 cluster 画像卡片

## v7.5 「Context bandit」— 画像 × 特征 × 动作
- 把 v6 LR 扩展为"每个 cluster 一组 LR 参数"（contextual bandit 起步），每个 cluster 独立学习自己的权重
- 打分：新方案 vs v7 baseline 在 4 类用户上各自的表现

## v8.0 「协同过滤起步」— (Mock) 多用户矩阵 + Item-based CF
- **迭代目标**：从"只看自己"到"借鉴相似用户"
- **关键改动**：
  - 生成 mock 100 用户 × 500 题目评分矩阵（稀疏度 80%）
    - 评分由 v7 画像 + 能力模拟生成（可控）
  - Item-based CF：
    - 相似度 = Cosine(题目的用户评分向量)
    - 预测分数 = weighted sum（最相似 N 题的用户评分）
  - 融合：v7 规则(0.6) + CF(0.4) 线性组合
- **并行方案**：v7 冠军 vs CF-融合 vs CF 纯
- **成功指标**：融合方案 5 折 CV 的 RMSE < 纯 v7
- **产出物**：相似度矩阵热点图（Top-20 topic pairs）

## v8.5 「冷启动快速画像」— 前 10 题校准问卷
- 新用户首次进入，展示 3 个"选你想学的科目/想达到的难度"问题 + 7 道校准题（按 IRT 选，信息量最大），10 题后给出初始画像
- 对比：有 vs 无前 10 校准，冷启动阶段 (前 30 卡) 正确率在目标区间的比例

## v9.0 「知识追踪 BKT (mock)」— 每个 Topic 的掌握概率
- **迭代目标**：从"题目级能力"深入"知识点级掌握"
- **关键改动**：
  - 对 syllabus 中 200+ topic 各自维护 BKT 参数：
    - P(L₀) 初始掌握概率
    - P(T) 学会后不遗忘（或学会概率）
    - P(S) 掌握但答错（slip）
    - P(G) 未掌握答对（guess）
  - 每次答题（根据 topicCode 关联）用 BKT 公式更新 `P(L|evidence)`
  - 推荐策略：
    - P(L) 低 → 推 prereq 链条上的题目/知识卡
    - P(L) 高 → 推后续 topic，避免原地踏步
- **打分系统升级**：新增 `masteryGain` 维度（每 100 题提升 P(L) 的总 gain）
- **成功指标**：BKT 方案 masteryGain ≥ v8 + 10%
- **产出物**：Top-10 高频 topic 的 P(L) 学习曲线

## v9.5 「prereq 图谱推荐」— 前置依赖不满足时不推进阶题
- 在 v9 BKT 基础上硬约束：
  - topic prereq 链上 P(L) < 0.7 时，不推该 topic 的 hard / medium 题
  - 自动退回到 prereq 内容
- 观察：错误率在 3 跳 prereq 回流后是否下降

## v10.0 「第二阶段验收」— 算法组合赛
- 6 种方案（v5 冠军 / v6 LR / v7 画像版 / v8 CF 融合 / v9 BKT / v9.5 prereq 约束）
- 评估维度新增：
  - Topic 覆盖率（100 卡内触达 unique topic 数）
  - 前置依赖满足率
  - 学习增益 BKT masteryGain
- **产出物**：
  - `ab-finals-v10.md` 阶段报告
  - 推荐引擎 v10 基线确定
  - 下一阶段 5 版本要解决的 3 个短板（从评估中挖掘）

# 第三阶段：系统协同 (v11.0 — v15.0)

## v11.0 「真数据接入」— 对接 syllabus-data.js + practice-engine.js 真题库
- 把 practice 页面每科真实 120 题解析为卡片，按 topicCode 与 QB 简单题合并去重
- 打分：真实题库与简单题库的质量分对比报告

## v12.0 「SRS 深度集成」— Spaced Repetition 与抖科刷卡通电
- 每道题做对/做错 → 写入 SRS（EF 因子 + 下次复习时间）
- SRS 到期卡自动插入推荐队列（权重 × 2）
- 对比：启用 vs 不启用 SRS，7 天回访正确率对比

## v13.0 「streak / analytics / notes 贯通」
- 顶部 streak 与全局 streak.js 真实同步
- 每答 20 题触发学习报告卡（analytics 汇总）
- 错题支持"记笔记"按钮 → 写入 notes.js
- 打分：新增 `toolAdoptionRate` 维度（streak/SRS/notes 使用率）

## v14.0 「多模态内容」— 公式渲染 + 图表 + 音频 + 概念图卡
- MathJax / KaTeX 接入（公式题友好）
- Concept map 卡片：当前 topic → prereq 3 节点小图
- 题型新增：听音频选择题（mock 播放按钮 + 占位音频）
- 打分：多模态卡片 vs 纯文字卡片的停留时长 / 正确率 / 反馈分对比

## v15.0 「完整 A/B 实验后台」
- 每次会话从方案池随机分配一组（weighted sampling）
- 会话结束写 `experiment_logs`：方案名 + 5 维度打分 + 会话长度
- 统计显著性：t-test / Mann-Whitney U，方案间差异 ≥ 5 分且 p < 0.05 才宣布胜出
- Dashboard 新增"实验台"tab：当前跑的方案、样本量、置信区间、胜出状态
- **产出物**：实验台规范文档 `ab-platform-v15.md`

# 第四阶段：生产打磨 (v16.0 — v20.0)

## v16.0 「个性化学习路径」— 用户输入短期目标 → 路径推荐
- 目标选项：两周突击 SAT Math / 一个月 IGCSE 化学入门 / ...
- 按目标拆解：每周 topic 覆盖量 → 周循环推荐
- 打卡机制：路径完成度徽章
- 打分：目标 vs 实际 P(L) 达成率

## v17.0 「深度画像学习」— 多臂老虎机 → 汤普森采样
- v6.5 的 ε-greedy 升级为 Thompson Sampling（Beta-Bernoulli），每卡片有 α/β 参数动态更新

## v18.0 「深度模型模拟」— (Mock) LSTM 序列推荐

## 迭代工作流 SOP（每个版本都要做）

```
1. 需求分析 → 明确"要解决的一个问题 + 一个核心指标"
2. 方案设计 → 至少 2 套并行方案（A baseline, B 实验）
3. 代码实现 → 在 scoring engine 里登记方案到 simulateAB 注册表
4. 仿真测试 → 100 会话 × 50-80 卡，得到排名 + 雷达图
5. 人工审阅 → 随机抽 5 条会话，检查"算法是否在做诡异的事"
6. 真实验 A/B → 小流量上线（30% 用户进 B 组），至少 50 会话样本
7. 统计显著 → p<0.05 & 提升≥3分 → 合入 baseline；否则分析原因归档
8. 文档归档 → /docs/douke-versions/vX.Y.md 记录改动 + 数据
9. 数据导出 → DoukeScoring.exportAll() 存一份快照 JSON
```
