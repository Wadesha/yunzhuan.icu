技术方案讨论

🔌 数据层：Supabase Database vs Vercel KV

现状：已有 Supabase Auth 和 Vercel KV（统计用）

Supabase Database 方案
  • 关系型数据，适合复杂查询
  • RLS 行级安全，数据隔离
  • 与已有 Auth 无缝集成
  • 支持实时订阅
Vercel KV 方案
  • Redis 速度快
  • 与现有统计代码复用
  • 但不适合复杂关系数据
  • 查询能力有限

推荐：用户数据用 Supabase Database，KV 继续存访问统计。两套各尽其职。

📅 截止日期提醒实现方案

  • 方案 A：浏览器 Notification API + Service Worker 定时检查（纯前端，无需后端）
  • 方案 B：Vercel Cron Job + 邮件推送（需要用户邮箱，用 Resend / SendGrid）
  • 方案 C：Web Push Notification（VAPID 协议，可离线推送）

推荐：先做方案 A（零成本），后续迭代加方案 C。邮件提醒作为高优先级功能单独评估。

技术方案讨论

💬 评论系统选型

Giscus (GitHub Discussions)
  • 零后端，开箱即用
  • GitHub 账号体系
  • 支持深色模式
  • 无广告，开源
自建评论系统
  • 完全可控，可定制
  • 与站内账号体系打通
  • 开发成本高
  • 需要反垃圾机制

推荐：第一阶段用 Giscus 快速上线，验证需求。用户量起来后再考虑自建。

🛡️ 内容审核方案

  • 前置审核：新用户首帖需审核（人工 + 关键词过滤）
  • 自动审核：接入第三方内容审核 API（如阿里云内容安全、腾讯云内容安全）
  • 用户举报：每帖带举报按钮，社区共治
  • 成本预估：第三方 API 约 ¥0.002/次，1 万条内容 ¥20，早期可接受

⚡ 富文本编辑器选择

  • TipTap：基于 ProseMirror，现代、轻量、可扩展（推荐）
  • Quill：成熟稳定，生态好，但包体较大
  • Markdown 编辑器：如 EasyMDE，技术向用户友好，但普通用户有门槛

推荐：Markdown 先行（开发成本最低），后续再上 TipTap 富文本。

为什么单独做竞赛板块
  • 背景提升是美本申请的核心环节，竞赛是最主流的背景提升方式之一

  • SEO 流量入口："xx 竞赛含金量"、"xx 竞赛报名时间" 等长尾词

📄 标准竞赛详情页结构

  1. 基本信息卡片：全称、缩写、主办方、官网、报名时间、比赛时间、参赛费用

🔍 筛选器实现方案

纯前端筛选（推荐）
  • 开发快，无需后端
  • 响应快，无网络延迟
  • 适合 40-100 条数据规模
  • 可静态托管
后端筛选
  • 支持复杂查询
  • 数据量大时性能好
  • 开发成本高
  • 需要运维

推荐：Phase 1/2 纯前端筛选（数据量 < 200 条完全没问题），到 Phase 3 再考虑后端。

🤖 AI 选校匹配算法

核心思路：基于历史录取数据 + 用户背景特征，计算匹配度。

技术实现方案

准入控制

  • 邀请码 = HMAC 签名 + 过期时间 + 角色标识 + 一次性随机串，前端校验 + 后端二次校验
  • 登录态使用 HttpOnly Cookie + SameSite=Lax，JWT 短期（2小时）+ Refresh Token 长期（30天）
  • IP 绑定可选开启，开启后异地登录需重新验证邀请码
  • 敏感操作（导出数据、修改成员角色）需二次确认 + 操作日志

数据存储与隔离

  • 公开内容：继续使用纯静态文件 + JSON 数据，部署在 CDN
  • 协作内容：使用 Supabase（Postgres + Row Level Security），按 member_id 强制隔离
  • RLS 策略示例：feedback.member_id = auth.uid() OR auth.role() = 'admin'
  • 公开页面与协作数据通过前端 JS 异步拉取，不影响主站 SEO

细节页面设计原则（让"假"看起来像"真"）

  • 动态细节：用户档案中的姓名、年级、专业、奖项自动填充到所有模拟页（占位符替换）
  • 上下文一致：同一用户在同一学校的"模拟初稿"与"模拟面试回答"互相呼应（提到同一项目、同一人名）
  • 专业区分度：不同专业的面试题、文书题、推荐书单显著不同（CS vs 历史 vs 商科）
  • 时间标记：所有日期基于目标申请季（如 2026 Fall），不出现不合理时间
  • 多语言支持：所有页面同时提供中英双语版本，按用户偏好切换
  • 水印标识：页面顶部显著标识"模拟数据" + 免责声明，避免误读
  • 返回路径：每个细节页顶部固定"← 返回 {学校名} 模拟页"，保证可逆浏览

录取概率算法（模拟版）

function calcChance(user, school) {
  // 简化版 - 仅用于模拟演示
  const userScore = (
    user.gpa * 0.4 +
    user.testScore / 1600 * 0.3 +
    user.activities.length * 2 +
    user.awards.length * 5
  );
  const schoolAvg = school.avgAdmitScore;
  const stddev = school.stddev || 10;
  const z = (userScore - schoolAvg) / stddev;
  const prob = 1 / (1 + Math.exp(-z)); // sigmoid
  return Math.round(prob * 100);
}
